# 变更说明 · 1.0.3.11（2026-11-26）

## 一、产品改名

中文名：**WB驭档·模型智能换挡系统**　英文名：**WB-GearPilot**

覆盖：DSH 插件（Pro / Max）、网关（含管理界面）、Skill（wb-max-router）、MCP（wb-max-mcp）、
README 与 docs-open 文档、模型选择器的候选名称前缀（`WB路由·` → `WB-GearPilot·`）。

**技术标识零改动**（兼容性保证）：npm 包名 `dsh-wb-pro` / `dsh-wb-max` / `wb-max-mcp`、
skill name `wb-max-router`、MCP 工具名 `wb_route_plan` / `wb_route_execute` / `wb_route_health`、
HTTP 路由 `/router/*`、槽位名、触发词 `[WB-Max路由]`、仓库名 `dsh-bw-router` 全部保持不变。

## 二、修复

### 1) Pro「生成计划」无反应（P0–P3）
- **P0**：空草稿点「生成计划」不再静默吞掉点击，改为明确提示「请先在输入框写任务」。
- **P1**：「生成计划」按钮的 `disabled` 只依赖 `pending`，不再因草稿为空而点不动。
- **P2**：hint / error 提示卡不再被 hero / active 阶段门槛挡住；并加单实例仲裁（提示只在 dock 槽渲染），避免同一会话出现两张提示卡。
- **P3**：草稿读取增加 DOM 兜底——宿主的 `useInput().draft` 取空时，从 composer 的 `[contenteditable][data-composer-input]` 直接读文本，解决「已输入却判定为空草稿」导致按钮不可点的问题。

### 2) 切段回读误报「切换失败」
模型切换后回读校验把两侧键空间不一致地比较：`selection.current()` 已剥掉 `wb-gateway/` 前缀，
而计划里的 `targetKey` 未剥，于是「已切成功」仍被判为失败并提示「第 1 段模型切换失败」。
修复：`switchForStage` 统一用 `normalizeModelKey(targetKey)` 比较两侧（含 already-in-use 判定）。
