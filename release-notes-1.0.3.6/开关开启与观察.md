# 1.0.3.6 开关开启步骤与观察口径

> 默认策略：**先只观察，稳定后逐级开启**。本包出厂默认：B1 开、B3 开（不传档位＝零变化）、B4 关、B5 关、
> `context_governor=shadow`、`trim=false`、`error.allow_413=false`、`ROUTER_PRICE_ATTEST=1`（单源价格自证）。

| 能力 | 开关 | 默认 | 开启方法 | 观察指标 | 回滚 |
|---|---|---|---|---|---|
| B1 边界纪律 | `ROUTER_B1_DISCIPLINE` | 1 | 无需开；关闭设 0 | `GET /v1/route/discipline?range=7d` 的 `non_exempt_violations` | 设 0 并重启 |
| B3 自动化档位 | `ROUTER_B3_AUTOMATION` | 1 | 请求体/头 `automation_level=L1/L2/L3`；L1=现状 | plan 返回 `automation` 块；L2/L3 确认次数 | 不传档位即回 L1 |
| B4 影子判定 | `config/shadow_judge.json → enabled` 或 `ROUTER_B4_SHADOW=1` | false | 改 enabled=true（热加载） | `GET /v1/route/shadow?range=7d`：calls/ok/bad_output/latency；`/health.shadow` | enabled=false |
| B5 只读入口 | `ROUTER_B5_PASSTHROUGH=1` + key 的 `passthrough:true`（或 `ROUTER_B5_PASSTHROUGH_KEYS=<id/name>`） | false | 二开关都开；请求头 `X-WB-Route-Mode: passthrough` | 响应头 `X-WB-Model/Strategy/Usage-Kind`；账本 `passthrough=true` 行 | 关 env 或撤 key 权限 |
| 上下文治理 | `ROUTER_CTX_GOVERNOR` 或 `config/routing.json → context_governor.mode` | shadow | 改 `enforce`（需重启） | 账本 `ctx_gov.band`（pass/compress/reject）比例；响应头 `X-DSH-Context-*`；400 `context_window_exceeded` 次数 | 改回 shadow/off |
| 阶梯裁剪 | `context_governor.trim.enabled` | false | 置 true（仅 enforce 下生效；最多 `max_trims` 次） | 账本 attempts `trimmed` / `ctx_trim_retry` | 置 false |
| 413 出口 | `context_governor.error.allow_413` | false | 置 true（默认 400） | 状态码分布 | 置 false |
| 单源价格自证 | `ROUTER_PRICE_ATTEST` | 1 | 默认为开；回退旧双源快照设 0 | `/health.price_consistency`（single-source、27/27、drift 0） | 设 0 |
| 超时收回 | `config/routing.json → timeouts` | read 270s / stream 600s | 按需改（B0 数据驱动基线） | 账本 `attempts[].ms` 的 p99 | 改回旧值并重启 |

## 建议观察节奏
1. **第 1 天**：保持 shadow/关档，观察 `/health`、`/v1/route/report`、`/v1/route/discipline`、`/v1/route/shadow`；确认错误率与 p95 与升级前基线一致。
2. **第 2–3 天**：只把 `context_governor` 从 shadow 切 enforce（trim 仍关），看 `ctx_gov.band=reject` 比例与 400 次数；若 >1% 先回 shadow 分析。
3. **稳定后**：按需开 trim/413/B4/B5；每次只动一个开关，记录改动时间与回滚点。
4. **任何异常**：先关开关（不必卸载），再查 `/v1/route/report` 与账本 `ctx_gov`；回滚不删数据。
