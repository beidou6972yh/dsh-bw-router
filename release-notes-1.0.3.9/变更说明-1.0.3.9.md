# 1.0.3.9 变更说明（2026-11-24）

> 触发：2026-11-24 18:25「模型路由配置异常排查」会话报三个现象，其中 ② 是**真缺陷**——
> Max 卡里把三段模型分别钉成三段不同的上游模型，确认后**重新出计划会全部弹回策略链首位的默认模型**。
> 原则：只加**请求级钉选**这一条通路，不传时逐字节零差异；同时收口两个同源坑（原生回落白名单写死、空草稿点 Pro 无反馈）。

## 一、缺陷与根因

| 现象 | 根因 | 归属 |
|---|---|---|
| Max 三段钉选确认后，重出计划三路全弹回默认模型 | ① 卡片下拉只写 React 临时 state，**没有落到任何持久层**；② MCP 工具 `wb_route_plan` 只透传 `task/strategy/max_stages`，钉选**根本没发出去**；③ 网关按策略链首位选模，不认任何「请求级指定」 | 网关 + MCP + 客户端 |
| 卡片选到白名单外的新上游时，切模型报 model-unavailable | 客户端原生回落候选是**硬编码白名单**，新上游不在表里 ⇒ 只剩 `wb-gateway/<key>` 一条路，网关一异常就无兜底 | 客户端 |
| 空输入框点 Pro「没反应」 | 只置高亮与发送锁，不 publish 任何提示态，卡片不渲染 | 客户端 |

## 二、改动清单

### 1. 网关：请求级钉选 `stage_models`（主项）

- `POST /v1/route/plan` 新增可选字段 `stage_models`，形如 `{"s1":"<upstream>/<model>","s2":"…","s3":"…"}`，也接受 1-based 数字键 `"1"/"2"/"3"`。
- 优先级：**钉选 > learnedOverride > 策略链首位**；钉选**不写盘**、不进 learned override，只作用于本次请求。
- **fail-open**：未注册模型 / 非法段 id / 形状不对，一律记入 `stage_models_skipped` 并**继续出计划**，不返回 4xx；不传时行为与 1.0.3.8 完全一致（零差异）。
- 回显与审计：计划响应带 `stage_models`、`stage_models_skipped`；每段带 `pinned: true`，`learned_override.stages[].source = "session_pin"`，`learned_at` 保持 `null`（与学习型覆盖可区分）。
- 计划记账落的是**钉选后**的 `model_key`，因此执行侧 `model_mismatch` 校验不会误报。

### 2. MCP（Skill 侧）

- `wb_route_plan` 的 inputSchema 增加 `stage_models`，并原样下发到网关（对象类型校验，非法形状不下发）。

### 3. 客户端（Pro / Max）

- **钉选持久化**：按段 id 存 `localStorage`（`wb.max.stage.models`）；新建会话 / 刷新页面后从本地恢复，不再回退默认模型。
- **两条出计划通路都带钉选**：主按钮出计划、草稿直接出计划，均随请求发 `stage_models`；「取消」清空全部会话钉选。
- **原生回落白名单改为动态**：由网关 `/wb-max/models` 返回的已注册模型里自动收集上游 id，不再写死名单——新接入上游即刻获得原生回落候选。
- **空草稿点 Pro 给明确提示**：「Pro 已开启 · 请先在输入框写任务，会自动生成计划（也可点「生成计划」）」，不再静默。

## 三、版本与配套

- 网关 `VERSION`：1.0.3.8 → **1.0.3.9**（顺带修 `gateway/VERSION` 长期滞留 1.0.3.6 的问题）。
- 插件：`dsh-bw-router` / `dsh-wb-pro` / `dsh-wb-max` 0.2.4 → **0.2.5**。
- 包内文档目录：`gateway/docs-1.0.3.6/` → **`gateway/docs-1.0.3.9/`**；三份对外文档与 PDF 版本统一到 1.0.3.9。

## 四、验证

1. **新增 13 条钉选单测**（`gateway/tests/test_stage_models_pin.py`）：三路钉选生效、数字键等价、部分钉选、连续重出计划一致、未注册模型 fail-open、坏段 id / 坏形状跳过、空白值静默、不落盘、**钉选优先于 learnedOverride**。生产树与公开树各 **13/13 OK**。
2. **活体冒烟**（影子实例，独立端口，不碰生产）：不传钉选 → 三段全落策略链首位（复现原缺陷）；传三路钉选 → 三段精确落在指定模型，`pinned=true`、`source=session_pin`，估价按钉选模型结算。
3. **零差异**：不传 `stage_models` 时计划与 1.0.3.8 逐段一致（单测 `test_no_pin_is_zero_diff`）。
4. 网关回归与插件 vitest 见发布核对单。
